# Gyro

Android-приложение для моноколёс по Bluetooth LE: Kotlin, Jetpack Compose (Material 3, тёмная тема), MVVM, Room, Kotlin Flow. minSdk 26.

Название репозитория — KingSong, но приложение не привязано к одному бренду. Разбор пакетов лежит в отдельном модуле, и новый бренд добавляется одним классом.

## Что уже работает

**BLE-слой** (`app/.../ble`, `protocol/`)
- Поиск колёс. Фильтра по сервису нет, потому что многие колёса его не рекламируют. Узнаваемые имена показываются сверху.
- Подключение: служба UART → запрос MTU 517 → подписка на уведомления → определение протокола.
  - Сначала по GATT-сервисам определяется транспорт.
  - Потом по имени и по «отпечатку» потока байт определяется протокол. Благодаря этому узнаются и новые модели с незнакомыми именами.
  - Если автоопределение не сработало, протокол можно выбрать вручную.
- Автопереподключение с нарастающей паузой. Определённый протокол запоминается, и при обрыве посреди поездки повторного определения не будет.
- Foreground-сервис `connectedDevice` держит связь при выключенном экране. Уведомление показывает скорость, заряд, температуру и запас хода и умеет отключать колесо.

**Поддерживаемые колёса**

| Бренд | Модели | Статус разбора |

С незнакомой моделью известного бренда Gyro работает так:
- берёт ближайший известный формат пакетов и помечает его в интерфейсе как «новая модель»;
- определяет число ячеек батареи по напряжению (его можно исправить вручную).

**Дашборд**
- Крупный спидометр:
  - внешняя дуга — скорость, с меткой tiltback;
  - внутренняя — нагрузка (PWM);
  - дополнительно показываются заряд, напряжение (и на ячейку), ток батареи и фазный ток, мощность, температуры, поездка и одометр.
- «Сколько входит и выходит»:
  - энергия из батареи и энергия, вернувшаяся рекуперацией (Вт·ч и А·ч);
  - итоговый расход, доля рекуперации и Вт·ч/км;
  - пики мощности и рекуперации;
  - энергия, полученная от зарядки на стоянке, считается отдельно.
- Live-график мощности за 90 секунд: расход из батареи и возврат рекуперацией показаны разными цветами, поверх — линия PWM и уровень тревоги.
- Предупреждение до срабатывания tiltback:
  - по порогам PWM и близости к скорости tiltback;
  - по тренду: если нагрузка растёт, Gyro предупреждает за 1–2 секунды до достижения порога.
- Запас хода в км по текущему стилю езды: расход Вт·ч/км за последние 3 км. Ёмкость берётся из BMS, по модели или вводится вручную.
- Кастомные алармы (скорость, нагрузка, температура, ток, мощность, заряд, напряжение) с гистерезисом. Приложение не издаёт звуков и не вибрирует: сработавший аларм виден красной плашкой на дашборде, фоном в режиме «на руле» и рамкой оверлея.
- Напоминание «поставь на зарядку» при заряде ниже 30% — беззвучным уведомлением.
- Режим «на руле»: одна огромная цифра, экран не гаснет, фон подсвечивается перед tiltback и при сработавшем аларме.
- Оверлей поверх других приложений.
- Быстрые кнопки: сигнал, свет и блокировка. Блокировка работает только на месте и только на колёсах, которые её поддерживают (InMotion, Ninebot Z).

**Безопасность записи настроек** (`protocol/.../SettingsWriteGuard.kt`)
- Исходные значения настроек автоматически сохраняются в Room при первом подключении, до любой записи.
- Отправить команду записи без «пропуска» от `SettingsWriteGuard` нельзя. Пропуск выдаётся только если:
  - есть бэкап;
  - заряд не ниже 50%;
  - подтверждён каждый пункт диффа «было → станет»;
  - если новое значение выше исходного, выдано предупреждение и пользователь его подтвердил.
- Калибровка датчиков не реализована намеренно.

**Остальные вкладки** — это заготовки со списком планируемых функций, но часть данных уже показывается:
- **Батарея** — живые напряжения ячеек, разброс и слабейшая ячейка;
- **Колесо** — текущие настройки и бэкап;
- **Ещё** — история подключений.

## Архитектура

```
protocol/   чистый Kotlin/JVM, без Android — тестируется обычным JUnit
  WheelProtocol        общий контракт: decode / poll / encode / encodeSettings
  KingSong, Begode, Veteran, InMotionV1, InMotionV2, NinebotZ — реализации
  ProtocolDetector     транспорт + имя + сниффинг потока
  EnergyMeter, RangeEstimator, TiltbackPredictor, AlarmEngine, SettingsWriteGuard
app/
  ble/       GattClient (очередь GATT-операций на корутинах), BleScanner, WheelConnectionManager
  data/      Room (алармы, известные колёса, история подключений, снапшоты настроек), DataStore, RideMonitor
  service/   WheelService (foreground), беззвучные уведомления, оверлей
  ui/        Compose: дашборд, режим на руле, вкладки
```

Данные идут по одному пути: `WheelConnectionManager.wheel: StateFlow<WheelState>` → `RideMonitor.snapshot: StateFlow<RideSnapshot>` плюс `events: SharedFlow<RideEvent>` → ViewModel и сервис.

## Сборка

```
./gradlew :protocol:test          # 68 тестов протоколов и логики, Android SDK не нужен
./gradlew :app:assembleDebug      # APK: app/build/outputs/apk/debug/
```

GitHub Actions (`.github/workflows/android.yml`) на каждый push:
- гоняет тесты;
- собирает отладочный APK — его можно скачать во вкладке Actions, артефакт `gyro-debug-apk`.

### Выпуск версии

Готовые APK публикуются на странице [Releases](https://github.com/gghub433/KingSong/releases). Новую версию выпускает workflow «Release»: во вкладке Actions нажмите «Run workflow» и укажите версию (например `0.2.0`). Можно и так: запушить тег `v0.2.0`. Workflow прогоняет тесты, собирает release-APK (в release-сборке интерфейс работает заметно быстрее, чем в отладочной) и создаёт релиз `Gyro-<версия>.apk`.

**Подпись.** Android ставит обновление поверх, только если оно подписано тем же ключом. Репозиторий публичный, поэтому ключ хранится в секретах GitHub, а не в коде. Пока секретов нет, релиз подписывается отладочным ключом, а он на CI каждый раз новый, поэтому новую версию придётся ставить после удаления старой. Чтобы обновления вставали поверх, один раз создайте ключ, например в Termux:

```
pkg install openjdk-17
keytool -genkeypair -v -keystore gyro.jks -alias gyro -keyalg RSA -keysize 4096 -validity 36500
base64 -w0 gyro.jks > gyro.jks.b64
```

Затем в GitHub → Settings → Secrets and variables → Actions добавьте секреты:
- `GYRO_KEYSTORE_BASE64` — содержимое `gyro.jks.b64`;
- `GYRO_KEYSTORE_PASSWORD` — пароль хранилища;
- `GYRO_KEY_ALIAS` — `gyro`;
- `GYRO_KEY_PASSWORD` — пароль ключа.

Сам `gyro.jks` сохраните в надёжном месте: без него обновления подписать нельзя.

### На телефоне через Termux

Нужны телефон на ARM (почти любой современный), около 4 ГБ свободного места и желательно от 4 ГБ ОЗУ. Termux ставьте из F-Droid или с GitHub: версия из Google Play устарела и не получает пакеты.

```
pkg update && pkg install git
cd ~
git clone https://github.com/gghub433/KingSong
cd KingSong
bash termux-build.sh
```

Если репозиторий приватный, клонируйте с токеном GitHub: `git clone https://<логин>:<токен>@github.com/gghub433/KingSong`.

Что делает `termux-build.sh`:
- ставит `openjdk-17` и `aapt2` из пакетов Termux. `aapt2`, который скачивает Gradle, собран только под x86 и на телефоне не запускается, поэтому скрипт передаёт Gradle версию из Termux (`android.aapt2FromMavenOverride`);
- скачивает Android command-line tools (с проверкой SHA-256) в `~/android-sdk` и ставит `platforms;android-36` и `build-tools;35.0.0`;
- проверяет, что `aapt2` читает `android.jar` платформы 36;
- собирает `:app:assembleDebug`, отдавая Gradle треть ОЗУ (от 1 до 3 ГБ);
- кладёт `Gyro-debug.apk` в «Загрузки». Для этого один раз выполните `termux-setup-storage`, иначе скрипт напишет путь к APK. Установить можно и прямо из Termux: `termux-open app/build/outputs/apk/debug/app-debug.apk`.

Первый запуск скачивает около 1,5 ГБ и идёт 10–30 минут, повторные сборки — несколько минут. `bash termux-build.sh --clean` пересобирает с нуля; остальные аргументы передаются в Gradle.

Проект должен лежать в домашней папке Termux, а не в общей памяти (`/sdcard`, `~/storage`): там нельзя запускать файлы, и скрипт остановится с подсказкой.

## Происхождение протоколов и лицензия

Производители не публикуют протоколы. Раскладка пакетов, масштабы и команды взяты из открытого проекта [WheelLog](https://github.com/Wheellog/Wheellog.Android), который распространяется под лицензией GPL-3.0. Код декодеров написан заново под свою архитектуру, но опирается на те же форматы. Если приложение будет распространяться, безопаснее выпускать его под GPL-3.0.

## Проверено / не проверено

- Декодеры покрыты юнит-тестами на синтетических кадрах и на реальных кадрах Begode из документации WheelLog. На живом колесе пока не проверялись.
- Для отладки новой модели нужен дамп сырых пакетов. Лог сырых данных — в плане.
